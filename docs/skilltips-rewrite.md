## 验证入口

在插件仓根运行，所有数据路径显式提供：

```powershell
dotnet run --project tests/SkillOptimizer.Tests -c Release `
  -p:HostRuntimeDirectory=<匹配Host的运行时目录>

pwsh -File tools/Replay-SkillTips.ps1 `
  -RuntimeDirectory <冻结旧运行时> -DataDirectory <冻结旧数据> `
  -Packet <固定input.msgpack> -Output <旧结果复核.json>

pwsh -File tools/Validate-SkillTips.ps1 `
  -RuntimeDirectory <新Host运行时> -DataDirectory <冻结数据与新skill_planning.br目录> `
  -Packet <固定input.msgpack> -Package <新插件.zip> -Baseline <baseline.json> `
  -HistoryManifest <历史样本manifest.json> -OutputDirectory <本次输出目录>
```

本地尚未发布的依赖使用临时 NuGet source mapping 和独立缓存，见主 README。CI 使用共用 workflow 提供的 `UraTestHostRoot`。历史 manifest 的 `files` 包含 `path/sha256`，`learning` 包含 `before/request/after`，`finishes` 包含 `path/actualScore/expectedResidual`；原始路径与报文只存本地。

验证包括 2000 组费用与分数独立生成的穷举与 CP-SAT 对照（1724 组留下技能点）、最高分优先及同分最少花费、规则适配边界、三次重复结果一致、展示合计及进化后独立重评分、真实 Host 的 ZIP／原生库加载，以及错误路径／架构包拒绝。固定报文独立枚举 84 种进化配置并用多选背包求解，技能总分 20822、花费 9078，与 CP-SAT 一致。P0 修复构建包含 Host、SkillTips 和 SkillEffectPlugin；此前重写另验证了 EventLoggerPlugin 及其固定源码依赖。

历史学习费用 8470、1163 均与服务器一致；第一笔请求 81 个步骤、响应新增 54 个最终技能，验证了前置动作和最终持有计数的区别。两项未完成的技能计数均与服务器阈值截断结果吻合。两份重点结算 56298、78689 均完全一致。冻结历史 manifest 保留原始残差 0、6；验证工具按报文 SHA 核对原始期望，再断言修复后的残差 0、0，并输出变化，不加评分补偿常数。

`finish1.msgpack` 全档案包含 516 匹育成马、17114 条技能记录及 773 个不同 SkillID，无缺失 master。单次取整后 511 匹完全吻合，最大绝对残差为 1、绝对残差总和为 5；逐次取整时分别为 398、4、141。工具验证残差分布 `{-1:5,0:511}` 和未解释样本序号 `454,474,475,481,500`，保留原始服务器分数。

后续有界扫描 379 个响应，提取完整状态并与原档案去重，新增 683 个独立状态；生产 DLL 与独立 Python 计算全部一致。合计 1199 个状态中 1152 个精确、47 个高估 1 分。五维全部不超过 2000 的 710 个状态全部精确；47 个残差各有一个超过 2000 的属性，178 种高属性值中未见同值同时出现精确和残差的情况。原 2208、2271 分别有 6、2 个独立残差样本，2101 仍为 1 个。

一例只有固有技能 `120311 Lv3`、五维为 `[2226,479,1384,1211,1327]`，服务器总分 34172，技能 510、属性表合计 33663，仍高估 1 分，没有适性取整参与。47 例涉及的 159 种低属性值有 157 种也出现在精确状态；479、762 缺独立对照，且没有仅改变单一属性的隔离样本。因此证据强指向 2000 以上拟合段，尚未恢复服务器属性公式，不修改表项。

属性表提交 `510eb5872ea6437f36c15a633920abbd501e1f55` 声明 2001..2300 经实测校准、2301..2500 为拟合扩展。该段现有 500 项均等于 `RoundToEven(14280 + 18.25*d + 0.002*d*d)`，其中 `d=属性−2000`；这是现表的生成规律，不是已证明的游戏公式。属性分在同一输入快照内是常量，且在求解后才加到总评价，表偏差不会改变技能方案排序，但可能影响总评价、等级及距下一等级的显示。

## 性能与限制

一次相同 PowerShell 离线环境测量：旧完整入口约 147 ms、累计托管分配约 260 MiB、进程峰值约 237 MiB；单次取整修复入口首次约 0.88 s、74 MiB、384 MiB，后续约 0.68–0.69 s、1 MiB。具体每次值存于 `artifacts/skilltips-rounding-fix/result.json.metrics.json`。首次包含 JIT、原生库加载和校验；峰值包含整个回放进程，累计托管分配不包含 OR-Tools 原生分配，不能当作插件常驻内存或泄漏指标。

Rust locked Release 构建及 PE x64／导出检查在重写时通过；P0 修复未改原生代码，复用该桥接 DLL，Cargo 当前没有原生单元测试。没有在真实游戏执行本次学习模型预检、替换、最终学习或进化，也没有运行完整终端交互验收。紫技＋白技、白技上下位、紫技＋金技的临时模型费用仍须实机核对。固定报文及历史档案校准不足以证明所有服务器计数及评分规则。

发布须配套更新生成数据、包含单次取整评分的 Host、本插件及 SkillEffectPlugin；本地构建使用当前源码的 SDK `2026.11.1.2`。OR-Tools 在 ZIP 内，Hachimi 桥接 DLL 单独交付。本次仅在本地实现和验证，没有提交、推送或部署。

PE 导入检查确认 OR-Tools DLL 还依赖系统的 `msvcp140.dll`、`vcruntime140.dll` 和 `vcruntime140_1.dll`。遵循 [Google 的 Windows 安装要求](https://developers.google.com/optimization/install/dotnet/binary_windows)，使用 Microsoft Visual C++ x64 Redistributable；本次验证机器已具备运行环境，未验证缺少该运行库的干净 Windows。

原 `artifacts/skill_tips_bridge.dll` 被正在运行的进程占用，重写打包时按保护规则停止覆盖。单次取整修复独立产物位于 `artifacts/skilltips-rounding-fix/deliverables/`，包含 ZIP、桥接 DLL 和 SHA-256 清单；最终回放使用此目录的 ZIP 及对应 `runtime/` Host。
